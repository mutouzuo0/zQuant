## 2. 门禁与验收纪律（Q 全项通过的门槛）

```bash
# 快速门禁（排除 slow/network/m5_deferred）
pytest
# 全量 + 视告警为错误（Q 验收口径）
pytest -W error -W "ignore::starlette.exceptions.StarletteDeprecationWarning"
# 其余门禁
ruff check zquant tests && ruff format --check zquant tests
mypy zquant
lint-imports
```

### 2.1 `pytest -W error` 的三个坑

1. **`filterwarnings` 列表顺序**：Python 的 `warnings.filterwarnings` 是**前插**（prepend），
   所以列表**最后一条最先匹配**。要让「星标第三方告警忽略、其余告警报错」，必须写
   `["error", "ignore::starlette.exceptions.StarletteDeprecationWarning"]`——
   `error` 置前、`ignore` 置后。反序会导致 starlette 告警照样报错。
   见 `pyproject.toml [tool.pytest.ini_options] filterwarnings`。
2. **CLI `-W error` 会覆盖 ini**：命令行 `-W error` 追加在最前，会盖过 ini 的 ignore；
   所以显式跑 `-W error` 时**必须再追加同一个 ignore**（见上命令）。普通 `pytest`
   （ini 已含 `error`）即可达到「告警即错误」效果。
3. **测试探针必须关文件**：所有 exec 进策略脚本的 probe 落盘必须用 `with open(...) as _f:`
   而非 `json.dump(..., open(PROBE, 'w'))`——不关文件会产生 `ResourceWarning: unclosed file`，
   在 `-W error` 下直接红（M2-Q 已修 28 处，新增探针沿用此写法）。

### 2.2 验收纪律（4.9/4.9.2）

- **黄金用例六要素逐笔**（订单/成交/现金/持仓/费用/净值），禁止只看最终收益；
- **禁止以「与官方回测同量级/收益接近」验收**——多个错误可能相互抵消后收益仍接近；
- 新期望值必须手算，禁止「跑一遍拿输出当期望」（防自证）。

### 3.1 需要特别留意的偏差

- **run_daily 时刻折叠 15:00**：两平台日线回测盘中时刻一律折叠收盘执行并记
  `semantic_degradation`（`every_bar/open/close/15:00` 不记）。
- **golden bridge 的 include_today 近似**：平台版 bridge 的 `_DriverProvider.history`
  忽略 `include_today`（始终含当日）——g10 可见性用例在平坦价下验证钩子接线，不验证
  数值区分。
- **jq_portfolio_view.positions 键 = 平台外部码**（`600156.XSHG`，4.4 投影表），
  与官方 `context.portfolio.positions[security]` 对齐；改键需同步 golden g11 断言。

## 4. 核心纪律提醒（延续 M0-M1，勿回归）

1. **密钥纪律**：token/key 只进 `config/secrets.json`（已 gitignore）或 `ZQUANT_*` 环境变量；
   代码/测试/文档/示例一律占位符。
2. **不入库清单**：`config/secrets.json`、`config/settings.json`、`data/`、`results/`、
   `.cache/`、`zquant.db*`、`.zcode/`。
3. **价格语义（3.14）**：`raw_price` 是唯一记账/撮合基准；复权价只用于指标研究，
   不许把复权价喂给撮合。
4. **确定性（8.8）**：禁止未播种随机（seed=42）；dict 遍历先排序；时间戳整数毫秒。
5. **import-linter 契约**：adapters 禁 import `engine.broker/account/metrics`；data 禁 import
   `engine`；research/ml 禁 import `server`。
6. **文件头注释**：每个 `.py` 必须带 `# coding:utf-8` + `@author 木头左` +
   `@create_time/@update_time` + `@description`；新建两时间同值，修改仅更新 `@update_time`。
7. **接口变更回写**：改接口 → 回写设计文档并升版本号 → 更新 `.zcode/plans/` 计划进度
   （M2-P4 例：fills 增列 `bar_volume/participation_rate`，设计 8.3.3 已回写升版）。

## 5. 数据准备与常用命令（M2 新增）

```bash
# 完整数据获取（六步管道: 覆盖→增量→归一→去重→原子→缓存失效）
zquant fetch --codes 510300.SH,510500.SH,159915.SZ --start 2024-01-01 --end 2024-12-31 \
             --sources akshare,tushare --resume
zquant fetch --master                  # 主数据全量 upsert + 快照留档
zquant fetch --import <dir>            # 导入目录任意 CSV（3.5 嗅探 → 去重合并入库）
zquant fetch --dry-run --codes ...     # 仅覆盖检查（幂等: 重复 fetch → 零下载零写入）

# 只读即席查询（禁 DDL/DML, 写面语句拒绝）
zquant sql "SELECT trade_date, close FROM read_csv_auto('data/kline/etf/day/*.csv')"

# 对比/谱系
zquant compare <r1> <r2> [--csv navs.csv]   # 8.4 指标对照 + 净值对齐（≤6 run, 差异列高亮）
zquant lineage [<run_id>]                   # parent_run_id 谱系树
zquant diff <r1> <r2>                       # 策略源码 + 参数归一差异
zquant rerun <run_id>                       # params_json 原样重跑, parent 指向原 run
```

> 幂等保证依赖覆盖检查的「期望交易日」语义：优先 `data/calendars/trade_days.csv`，
> 缺省退化为周一~周五——周末/节假日不构成缺失，重复 fetch 不重复请求。
